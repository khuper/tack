# Changelog

## Unreleased

- Redesigned the `tack watch` deckhand as pixel art and put it back on the screen (it had been dropped in the March watch refactor). Half-block cells give two independently coloured pixels per character, so the sailor is a real 7×9-pixel figure with a cap, breton stripes and a walk cycle, crates are shaded and stack on a wooden dock, and the water is a two-tone swell; no new dependency is needed. The scene is driven by real activity: a scan sends the deckhand walking the deck with a sweep beam, an agent event has them hauling a crate to the hold with a signal ripple, each write-back docks a crate, and drift flags the front crate. Motion is eased, colors are a restrained hex palette that degrades to 256 colors, the water is a slow gradient swell, the layout adapts from 44 to 76 columns with compact labels, and every frame is generated by a pure, tested function. `a` pauses it; `--no-animations` and `TACK_ANIMATIONS=off` render a still frame.
- Fixed decision parsing for hyphenated words: `- [date] Prefer session-first flow - reason` split at the hyphen inside `session-first`, so the decision read "Prefer session" in `tack://session`, the handoff, and the briefing. The separator now has to be a spaced hyphen (or `--`) or an em dash; a hand-edited line with a hyphen touching one side, such as `Foo -bar`, is skipped.
- Fixed handoff markdown mangling Tack's own text: the summary line rendered as `1 system_s_` and implementation-status anchors as `implemented_src/a.ts_` because the markdown defanger also ran over generated parentheses. Repo-provided text is still neutralized.
- Tightened cross-session pattern grouping: two notes that cite the same file were merged on a single shared word, so unrelated discoveries were reported as agents "independently finding" the same thing. Sharing a file now requires at least two shared words.
- Wired the Bun unit suites (`tests/engine`, `tests/lib`, `tests/detectors`) into `npm run test:unit` and a GitHub Actions workflow; they had not run in any script, and eight of them had drifted out of sync with the code.
- Fixed a false `constraint_mismatch` when a project detects several values under one system id (Prisma over Postgres yields `db=prisma` and `db=postgres`): the check compared only the first signal, so `constraints: { db: postgres }` raised drift that never cleared. The constraint now holds when any signal under that id satisfies it.
- Fixed one scan appending duplicate drift items for the same signal, and replaced the three-digit `Math.random()` drift id with six hex characters from the CSPRNG checked for uniqueness; collisions had made accept/deny act on the wrong item.
- Fixed handoff archiving keeping handoffs by branch name instead of by age (stems are `<branch>_<timestamp>` and were sorted as plain strings), and two handoffs generated in the same second overwriting each other. `tack://session` now lists the newest decisions first under "Recent Decisions" instead of the oldest.
- Fixed `log_decision` and `checkpoint_work` accepting newlines inside a decision, which forged back-dated entries and headings in `decisions.md` that every reader then served as recorded memory. Decisions are collapsed to one sanitized line with a length cap, and every MCP tool argument now has a maximum length.
- Fixed the MCP server ignoring SIGINT/SIGTERM (it logged the disconnect and kept running), a telemetry flush that could take the server down with an unhandled rejection, `checkpoint_work` throwing away its note writes when a later decision write failed (it now reports per-write outcomes in an `errors` field), and `get_briefing` rejecting a `tools/call` that omits `arguments`.
- Hardened the untrusted-content sanitizer: every Unicode format character and the invisible fillers it missed are stripped, and the wrapper-tag defang recognises fullwidth and combining-mark spellings of the tag.
- Fixed the auth detector reporting `duplicate_auth` on any Clerk project: route identifiers such as `useUser` are shared between providers and were matched for every system, in every file including README. Route patterns now only enrich a system its package or config already proves, and only source files are searched.
- Fixed git change detection when `.tack/` lives in a subdirectory of the repository: listings mixed root-relative and project-relative paths, Tack's own log file tripped the write-back warning, and `tack diff` could not read committed `.tack` files. A path listing that times out or fails is now reported as an incomplete scan instead of a clean repo.
- `tack diff <ref>` exits 1 on an unknown ref, `tack watch --plain` exits 1 when it cannot start and anchors on the project root instead of the cwd, a scan that throws inside watch is reported instead of crashing, `tack note --type bogus` exits 1, `--message 2024` is no longer coerced to a number, and a spec.yaml that exists but does not parse is reported as such instead of "No spec.yaml found".
- `tack setup-agent` is idempotent under formatters: instruction files end with a newline, the block keeps the file's CRLF endings, a BOM or whitespace around the markers no longer reads as "malformed" or duplicates the block, and markers shown inside a fenced code block are ignored.
- `tack setup-mcp` keeps user additions to the `tack` server entry (a `disabled` flag, a timeout, extra env vars) instead of replacing the entry on every rerun; a customized Codex table that would have to be rewritten downgrades to a manual snippet naming the extra keys, and a JSON config with a duplicate key downgrades to manual instead of dropping one.
- Local state stays out of git in linked worktrees, submodules and nested project roots (the exclude file is resolved through `gitdir`/`commondir` and patterns are anchored from the toplevel), and the drift lock, claim journal, atomic-write temp files and setup-mcp lock are excluded too.
- `tack init` now initializes the current directory when it carries a project manifest (`package.json`, `pyproject.toml`, `go.mod`, ...), so a package inside a monorepo gets its own `.tack/` and name instead of the repository root's, and prints the absolute path it wrote. A directory with no manifest still falls back to the repository root.
- Scans and `tack watch` no longer skip source directories that happen to be named `build` or `env`: only a root-level `build/` and an `env/` that is a Python virtualenv (has `pyvenv.cfg`) are ignored.
- Denying an undeclared system no longer raises a second `forbidden_system_detected` alert for the same system on the next scan; one verdict is enough. A system forbidden in the spec from the start still alerts.
- Fixed the NDJSON tail reader corrupting the first entry after a rotation, rotation with a non-positive budget keeping everything, `compactNotes` erasing lines it could not parse and rewriting the file when nothing was old, `tack --version` in the bun bundle reading the wrong package.json, and pyproject names being taken from a `[[tool.uv.index]]` or source table instead of `[project]`.
- Stopped change detection from reporting a partial result as a clean one: `tack watch` now says so when a listing is too large to read instead of showing a quiet repo, `readFileAtRef` returns tracked files byte-for-byte rather than trimmed (an empty file no longer reads as missing), and changed paths keep leading and trailing spaces that are part of the filename.
- Fixed silent change-detection failure on busy repos: Node caps `execFileSync` output at 1MB and throws ENOBUFS past it, which the git helper swallowed as "no output", so a worktree with more than a few thousand pending paths reported zero changed files and any tracked file over 1MB read back as missing at a ref. The budget is now 64MB, and an over-budget listing warns once instead of passing off an incomplete scan as a clean one.
- Fixed changed-file detection for non-ASCII paths: git's default `core.quotePath` returned `café.ts` as the literal `"caf\303\251.ts"`, so the file that actually changed dropped out of drift detection, handoff `related files`, and status while an unresolvable path was reported in its place. All path listings now use `-z` and split on NUL, which also disambiguates paths containing a newline.
- Hardened the `.tack/` write boundary: the `.tack/` and `.tack/handoffs/` roots must now be real directories (a checked-in `.tack -> .git` symlink can no longer redirect writes), NDJSON rotation refuses any symlink, and all state files are written atomically (temp file + rename) so a crash or concurrent reader never sees a torn file.
- Hardened the untrusted-content sanitizer: lone CR / CRLF can no longer forge line structure inside the `<untrusted_project_context>` wrapper, and the invisible-character strip now also covers U+061C, variation selectors (U+FE00-FE0F, U+E0100-E01EF), and the Hangul fillers.
- Made drift state loss-proof: a `_drift.yaml` that fails to parse or contains entries a given Tack version cannot represent is quarantined and never rewritten (accepted/rejected resolutions survive), the corrupt-file warning fires once per process instead of per scan, watch mode stops looping notifications while the file is unreadable, and drift auto-dismissals from older versions migrate to the reopenable `disappeared` status.
- Added project-scoped MCP config generation (`tack setup-mcp`, and `tack setup-agent` by default) for Claude Code, Cursor, VS Code/Copilot, Gemini CLI, Codex CLI, and opencode, with surgical JSON/TOML merging that preserves unrelated keys, comments-bearing `.jsonc` files, indentation, dominant line endings, and a leading UTF-8 BOM; filesystem errors on one client downgrade to a pasteable snippet instead of aborting the batch, and config writes are atomic.
- Added `--platform win32|posix` to `setup-agent`/`setup-mcp` so mixed-platform teams can generate either command form deterministically (`--windows` remains an alias).
- MCP server modernization: tool annotations and titles, `outputSchema`/`structuredContent` on every tool, server `instructions`, and client identity resolved after `initialize` so clientInfo-derived agent names are honored. `get_briefing`/`check_rule` no longer claim `readOnlyHint` (they append to `.tack/` logs and stats).
- Declared the `zod` runtime dependency, moved to `@modelcontextprotocol/sdk` ^1.30, raised `engines.node` to >=20, and reconciled the stale `bun.lock`.

## 0.1.3 - 2026-03-11

- Tightened the trust-loop release story around one canonical proof path: run `tack setup-agent`, keep `tack watch` open, start a labeled MCP session with `TACK_AGENT_NAME=... tack mcp`, and confirm `READY`, `READ`, then `WRITE`.
- Made watch semantics easier to trust during reconnects: same-agent new sessions now show `reconnected to Tack MCP (new session)` instead of looking like silent disconnects.
- Unified plain and Ink watch around the same shared session controller so MCP activity, repo-change warnings, inactivity handling, and scan triggers stay behaviorally aligned.
- Clarified the first-run agent flow in the docs: run `tack setup-agent`, start the MCP server with `TACK_AGENT_NAME=... tack mcp`, and keep `tack watch` open as live proof that the agent actually used Tack.
- Updated package metadata to describe Tack as accurate project memory for coding agents with guardrails and handoffs.
- Added explicit install verification in `tack watch`: waiting for first agent read, successful `tack://session` read, and first memory write-back.
- Reworked `tack setup-agent` into an idempotent installer: `tack setup-agent` now bootstraps or updates supported agent files by default, resolves clean aliases like `cursor`, reports `installed` / `updated` / `unchanged`, and avoids partial writes when a target file is malformed.
